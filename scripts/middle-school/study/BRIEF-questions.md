# 중학교 문제 작업 지침 (과 하나)

정수학원 중학교 최종통합자료용. 답은 한국어. 작업 폴더 c:\video-app, 운영 DB에 바로 들어간다. 모델 API 호출 금지(직접 읽고 직접 쓴다). 커밋·푸시 금지. 소스 코드(src/) 수정 금지.

도구 (Bash, 앞에 `PYTHONIOENCODING=utf-8`):
- `python scripts/middle-school/study/src.py list|text|png|hwp …` 원본 보기 (사용법은 파일 머리글)
- `node --env-file=.env.local scripts/middle-school/study/qbank.mjs dump|study|patch <학년> <과> [--적용]` (형식은 파일 머리글)
임시 그림은 스크래치패드에. PNG는 Read 도구로 본다.

## 1. 본문학습·대표유형 입력 → `scripts/middle-school/study/data/<학년>-<과>.study.json`

- 「본문학습 STEP2 커뮤니케이션」(step2.pdf, area 의사소통): 뒤쪽 「확인문제」의 순서 배열하기 · 주요 표현 영작하기 · 빈칸 채우기. 앞쪽 설명·Dialogue 학습은 넣지 않는다.
- 「본문학습 STEP3 교과서 속 문법」(step3.pdf, area 어법): 「확인문제」의 Check up! · Level up!. 앞쪽 문법 설명·Check Check!·교과서 속 해설은 넣지 않는다.
- 「대표유형 풀어보기」(step7.pdf): 전 문항. area는 내용대로 의사소통·어법·본문.
- 정답·해설은 그 PDF 뒤쪽. 해설은 핵심만 짧게 옮겨도 된다. 원본에 정답이 없거나 번호가 그림이라 안 읽히면 해설을 보고 채운다.

원본 PDF 함정:
- 글자 추출은 차례가 뒤섞이고, ①~⑤가 그림이라 빠지며, 일부 글꼴 한글은 깨진 글자(㷛㿓 등)로 나온다. **쪽 그림을 봐서** 차례·밑줄·한글을 확인한다.
- 밑줄은 글자로 안 나온다. 그림에서 보고 `<u>…</u>`로 표시한다. 「밑줄 친」 발문인데 밑줄이 안 보이면 발문에 맞게 동사 등에 표시하고 보고서에 적는다.
- 「zb3)」 같은 표시, 쪽 머리·꼬리, 저작권 글은 넣지 않는다.
- ⓐ~ⓔ 고르기 보기는 choices ["ⓐ","ⓑ","ⓒ","ⓓ","ⓔ"]. (A)(B) 짝 보기는 "to do - cold"처럼 " - "로 잇고 표 머리 줄은 넣지 않는다.

서식(이대로): 
- 순서 배열: stem "다음 대화를 자연스러운 순서로 배열하시오.", body는 ⓐ… 한 줄씩 + 마지막 줄 "정답: (____) → (____) → …"(항목 수만큼), answer "ⓑ→ⓓ→ⓐ→ⓒ".
- 주요 표현 영작: stem "[영작] 우리말", body ["( 단어들 )", "→ ________________________________________"], answer 문장.
- 빈칸 채우기: 대화마다 한 문항. stem "다음 대화의 빈칸을 우리말에 맞게 채우시오.", body는 대화 줄(빈칸 "1)____________", 번호는 대화마다 1부터) + 마지막 줄에 힌트 "1) 처음으로  2) 걱정돼", answer "1) for the first time  /  2) worried".
- Check up!: 한 묶음을 한 문항. stem "[문법 이름] 우리말과 같도록 빈칸에 알맞은 말을 쓰시오.", body "1. She ______ … (우리말)" 줄들, answer "1. …  /  2. …".
- 쓰기 문항의 답칸 줄은 "____________________________________".

## 2. 예상문제 직접 풀기·고치기 → `data/<학년>-<과>.patch.json`

`dump` 뒤 `data/<학년>-<과>.yesang.json`의 숨김(review 있음) 아닌 문항을 **하나하나 직접 푼다**(규칙 검사로 끝내지 말 것). 묶음 문항은 group_lines가 지문. 고칠 것:
- 교사용 내용이 문제 글에 찍힘(정답 줄, 「(→…)」 풀이, 「(T)(일치)」, 우리말 정답표) → 지우고 필요하면 explanation으로. 답칸은 `<blank/>`.
- 파일 꼬리·표시(「정답」「PRE-STEP」「본문변형」), 표 머리 줄(「ⓐ ⓑ」「(A) (B)」), 탭 → 지운다. 보기 안의 탭은 " - ".
- 빠진 우리말: 발문이 「다음 우리말을…」인데 문장이 없으면 `src.py hwp`로 원본에서 찾아 body에 넣는다(파서가 한글 줄을 걸렀다). 영어 문제 글이 빠진 것도 원본 확인.
- 흩어진 보기(보기 일부가 body로 감), 오타(With Minus → With Minsu 등 명백한 것), 정답이 틀린 문항(풀이 근거를 why에).
- 그림·표가 꼭 있어야 하거나 원본으로도 못 고치면 review에 사유를 넣어 숨긴다. 대체 문항을 지어내지 않는다.
- 객관식 보기가 정답 둘이 되는 등 문제 자체가 불량이면 원본과 대조하고, 원본도 그러면 고치지 말고 보고서에 적는다.
원본 내용을 새로 쓰거나 다듬지 않는다 — 깨진 것만 고친다. `patch`는 먼저 미리 보기, 문제 0이면 `--적용`.

`dump`가 찍는 의심 목록은 참고일 뿐이고 전 문항 풀이를 대신하지 않는다. 대표유형·STEP3 객관식도 직접 풀어 정답과 맞춰 본다.

동아(이병민)은 학년에 「이」를 붙여 부른다(`qbank.mjs dump 중1이 2`, `src.py text 중1이 2 step3`, 파일 `중1이-2.study.json`).
임시 그림은 **스크래치패드 안에 과별 하위 폴더를 만들어** 넣는다(이름이 겹치면 다른 과 그림으로 덮어써진다).

정한 것:
- 객관식에 정답이 둘로 보이는 보기는 그 보기만 분명한 오답으로 고치고 why에 근거를 적는다. 발문과 내용이 안 맞으면(어법 ↔ 문맥) 발문을 맞춘다.
- 예상문제에 「각 빈칸에 한 단어씩」인데 빈칸이 뭉쳐 있으면 정답 낱말 수대로 나눈다.
- 숨김 문항도 원본으로 복원할 수 있으면 복원하고 review를 ""로 푼다. 그림이 꼭 필요한 것만 숨김 유지.
- 영역(area)이 명백히 틀리면 고쳐도 된다(patch에 area).
- 해설이 근거를 주는 오타 때문에 정답이 둘이 되면 그 오타를 고친다(why에 근거). 해설로도 판단 안 되면 숨기지 말고 보고.
- 지문을 답에서 찾는 서술형은 지문을 group_lines로 옮겨 검사를 통과시켜도 된다. 표는 줄글로 푼다(「요리법 - other chips: …」).
- 지문 위 이름(Show Host, Mina)은 원본이므로 둔다. 입력 중 고친 사소한 오타는 건수만 보고한다.
