# 내신콘서트 검수 지침 (과 하나, 입력이 끝난 뒤 · 넣기 전)

선생님 2026-11-04: 「넣을 때 문제랑 정답이랑 해설이랑 일치하는지 꼼꼼히 확인하도록!!!」
다른 사람이 입력한 `scripts/middle-school/study/data/<키>.concert.a.json`·`.b.json`을 **원본과 처음부터 다시 맞대** 고친다. 입력한 사람의 보고를 믿지 말고 직접 본다.
작업 폴더 c:\video-app. 모델 API 호출 금지. 커밋·푸시 금지. src/ 수정 금지. 다른 과 파일은 건드리지 않는다. 입력 규칙은 `BRIEF-concert.md`와 같다.

## 도구
- 원본 쪽: `PYTHONIOENCODING=utf-8 python scripts/middle-school/study/concert.py png <학년> <PDF쪽> <출력.png> [dpi]` → Read로 본다. 그림은 스크래치패드 안 `verify-<키>` 하위 폴더에.
- 검사: `PYTHONIOENCODING=utf-8 node --env-file=.env.local scripts/middle-school/study/qbank.mjs concert <학년> <과>` (미리 보기). 「해설 첫 번호 ≠ 정답」 같은 기계 점검도 여기서 나온다.
- 넣기(`--적용`): 지시받은 경우에만. 이미 DB에 들어간 과라도 고친 뒤 다시 넣으면 그 과 내신콘서트 문항이 통째로 바뀐다.

## 문항마다 볼 것(전 문항, 빠짐없이)
1. **문제 ↔ 원본 쪽**: 발문·지문·보기 글자, 빠진 줄, 밑줄 위치(<u>), 빈칸 수, 보기 차례. 번호가 원본과 같은지.
2. **정답 ↔ 원본 정답 쪽**: 책 뒤 정답 쪽의 그 번호 정답과 answer가 같은지(번호 밀림 주의). 복수 정답·서술형 정답 글자까지.
3. **정답 ↔ 문제**: 객관식은 정답 번호의 보기가 실제로 정답인지 직접 풀어 확인. 서술형은 조건(단어 수·주어진 단어·형태)에 맞는지.
4. **해설 ↔ 정답·문제**: 해설이 가리키는 번호·낱말이 answer·보기와 맞는지, 다른 문항 해설이 아닌지.
5. **묶음 지문(group)**: 지문이 그 문항 번호들의 것이고 원본 지문과 같은지.
6. **꼭지 빠짐**: 맡은 쪽 범위 안에 입력 안 된 문항·꼭지가 없는지(쪽마다 번호를 세어 본다).

어긋나면 원본대로 JSON을 고친다. 원본(책) 자체가 틀린 것은 고치지 않고 보고한다. 문제를 지어내지 않는다.

## 마지막 보고 (이것만, 짧게)
과, 전체 문항 수, 대조한 수(=전체여야), 고친 것(종류별 건수와 예 2~3개: 정답 밀림·해설 밀림·글자·밑줄·빠진 문항 추가 등), 책 자체 오류로 보이는 것(출처·번호·이유), `qbank.mjs concert` 미리 보기 결과(문제 0인지), `--적용` 했는지.
